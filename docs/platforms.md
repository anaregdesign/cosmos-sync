# Platform validation

Issue: [#11](https://github.com/anaregdesign/cosmos-sync/issues/11).

The integration fixture in `examples/flutter_smoke` validates the native SDK in
a Flutter application with real SQLite storage in the application's support
directory. Its deterministic authorized transport exercises durable offline
writes, closing and reopening the cache, exact replay after a lost response,
explicit stale-version conflict resolution, query watches, delete/recreate and
permission-loss purge. It never connects to Azure or creates cloud resources.

A passing native test requires launching the app and executing the fixture on
the named OS/device. Compilation alone is insufficient. Simulator results are
not physical-device results. Closing and reopening SQLite in the same process is
not an operating-system crash or a filesystem power-loss test. HTTP/OIDC/Cosmos
integration is validated separately by the cross-stack and emulator suites.

## Reproduce

```sh
cd examples/flutter_smoke
flutter pub get
flutter test integration_test/offline_sync_test.dart -d macos
flutter test integration_test/offline_sync_test.dart -d <ios-simulator-id>
flutter test integration_test/offline_sync_test.dart -d <android-emulator-id>
```

The fixture is unpublished (`publish_to: none`) and contains no signing team or
production credentials. Use a dedicated simulator/emulator; delete only devices
you created. The scenario deletes its own unique temporary cache directory after
the run. Native application background scheduling, encryption, production
identity providers, physical devices, Linux and Windows require separate
validation and are not inferred from these runs.

## Recorded results

Runs on 2026-10-03 used Flutter 3.44.6 (`ee80f08bbf`), Dart 3.12.2,
Xcode 27.0 (`27A266a`) and macOS 26.7 (`25G229`), on Apple Silicon.

| Target | Actual runtime result |
| --- | --- |
| macOS 26.7, arm64 desktop app | PASS: `COSMOS_SYNC_NATIVE_PASS macos`, `+1: All tests passed!`. |
| iOS 26.5, dedicated iPhone 17 Simulator | PASS: `COSMOS_SYNC_NATIVE_PASS ios`, `+1: All tests passed!`. |
| Android 14 / API 34, dedicated arm64 Emulator | PASS: `COSMOS_SYNC_NATIVE_PASS android`, `+1: All tests passed!`. |

The fixture deployment targets are macOS 12.0 and iOS 15.0 because Xcode 27
rejects the lower targets generated by this installed Flutter version. These
fixture settings do not establish the SDK's minimum supported OS versions.

Flutter stable pins `meta` 1.18.0. The original `sqlite3 ^3.7.0` dependency did
not resolve: its `hooks ^2.2.0` required a newer `meta` through `record_use`.
Using SDK constraint `sqlite3 >=3.5.2 <3.6.0` resolved SQLite 3.5.2, hooks 2.0.2
and record_use 0.6.0 with no dependency override. Constraints were verified from
the [official package metadata](https://pub.dev/api/packages/sqlite3), and the
fixture's lockfile records the resolved graph.

`flutter analyze` passed with no issues before native execution. Browser testing
uses the SDK's real Chromium suite separately; this fixture deliberately imports
`dart:io` and is native only.


The Android run used emulator 36.6.11.0, a new AVD with disposable user data and
an installed Android 34 Google APIs arm64 image. Existing SDK license acceptance
allowed Gradle to install required Android SDK Platform 35 during the build.
No new license acceptance was requested or submitted. The installed NDK was
28.2.13676358. Missing command-line tools reported by `flutter doctor` did not
prevent this actual build and runtime test.

The dedicated iOS Simulator was created, booted, tested, shut down and deleted.
The dedicated Android emulator was stopped and its disposable AVD directory
removed after the run. Existing simulators, AVD user data and physical devices
were not used. The fixture's unique SQLite directory was removed by its `finally`
cleanup on each platform.

The macOS tool emitted a foreground-window warning, but the application launched
and its UI integration test executed successfully. The results above mean the
native SQLite ABI, filesystem path and SDK scenario ran on the named platform;
they do not prove an arbitrary production app, device backup policy, encrypted
storage, suspended background sync or physical-device behavior.
