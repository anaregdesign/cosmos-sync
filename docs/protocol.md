# Wire protocol v0

All `/v1` endpoints require a validated OIDC **access** JWT. No client-provided tenant, owner or partition is accepted. Server grants authorize a `(tenant, subject)` identity and derive its partition. HTTPS is required outside local development.

- `GET /v1/session` -> `{scopeId: string, permissionVersion: string}`. SDK must compare both with its configured scope before sending queued data; a different identity or permission version clears the cache/outbox.
- `POST /v1/mutations` accepts `{operationId: UUID string, documentId: string, kind: "put"|"delete", data: JSON object|null, baseVersion: integer}`. Version 0 means absent. Server validates IDs, JSON size and baseVersion. Reply `{document: Document}`; a repeated operationId with identical payload replays its saved reply, a changed payload is 409 `idempotency_mismatch`. A stale baseVersion returns 409 `{code: "conflict", current: Document|null}`. SDK pauses that document and exposes the conflict until explicit retry/discard.
- `GET /v1/sync?cursor=<opaque>&limit=100` -> `{changes: Document[], cursor: string, hasMore: boolean}`. Omit cursor for initial replay of the retained journal. Cursors are tamper-evident and bound to scope and permission version; invalid/expired cursor returns 410 `{code:"resync_required"}`. No global ordering: only one logical partition's committed mutation sequence.
- `GET /v1/events?cursor=<opaque>` is optional SSE/polling hint delivery. Hints trigger `/sync`; reconnect always resumes through the durable cursor. Dart can use timed sync polling in this slice.

`Document` = `{id: string, data: JSON object|null, version: positive integer, deleted: boolean}`. Every committed mutation increments a partition sequence; this is also the document version. Deletion is a retained tombstone. An operation atomically changes the document, creates an immutable journal event and saves a receipt. No hard deletion, journal/receipt TTL or garbage collection is configured in v0, so an offline client's cursor and retry identity remain valid. Retention costs and future compaction require explicit resync semantics.

Errors are JSON `{code: string,...}` with 401/403 for authentication/authorization, 400 for invalid requests, 429/5xx retryable with Retry-After where available. SDK retains pending writes on network/429/5xx errors and purges/pauses on 401/403 (conservative policy). Mutations within one client are sent serially; the SDK durably assigns an exact baseVersion before first send and never rewrites an in-flight payload on retry. An explicit conflict retry creates a new operationId.
