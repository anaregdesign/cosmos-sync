# Security policy

Cosmos Sync is a preview SDK and BFF. Published prereleases receive fixes through
new versions; there is no production availability or response-time SLA. Use the
latest reviewed prerelease and consult the included protocol/security limitations.

Report vulnerabilities privately using [GitHub private vulnerability reporting](https://github.com/anaregdesign/cosmos-sync/security/advisories/new).
Maintainers must enable and verify this route before registry distribution.
If it is unavailable, do not publish exploit details in an issue; use an established
private channel to repository administrators and wait for the verified reporting route.

Include the affected version or source commit, platform, a minimal reproduction,
expected behavior, observed behavior and likely impact. Share redacted logs and
synthetic data. Never attach access/refresh tokens, Cosmos credentials, signing
keys, production documents or personal data. Do not test against other tenants,
production systems or resources you are not authorized to access.

The reporting form is private; it does not authorize a disclosure timeline or a
production test. Maintainers will coordinate reproduction, a fix and disclosure
with the reporter. Non-sensitive feature requests and general bugs can use
[GitHub Issues](https://github.com/anaregdesign/cosmos-sync/issues).
